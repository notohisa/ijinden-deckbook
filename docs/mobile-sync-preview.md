# スマートフォン向け同期テスト版

通常版は `/ijinden-deckbook/`、同期テスト版は `/ijinden-deckbook/sync-test/` に配信します。通常版のアプリを更新せず、両方のビルドを1つのPages artifactに含めます。

## 配信設定

- `VITE_GOOGLE_CLIENT_ID`: 設定済みの公開OAuthクライアントID。シークレットではありません。
- `SYNC_PREVIEW_REF`: このリポジトリ内のテスト版コミットの40桁SHA。ブランチ名ではなく確認したコミットを固定します。
- `Deploy to GitHub Pages` を **main** で手動実行します。mainへのpush時も同じ固定コミットのテスト版を含めます。
- テスト版は `VITE_SYNC_PREVIEW=1` と `--base /ijinden-deckbook/sync-test/` を指定してビルドします。
- ビルド・テストのjobには `contents: read` だけを渡し、Pages配信権限は別のdeploy jobに限定します。既存の `github-pages` 環境のmain限定設定は維持します。

## データと確認

- テスト版の端末内デッキ・アカウント選択情報は通常版と別のキーを使用します。通常版のデッキを自動移行しません。
- Google Driveの保存先はPCテスト版と同じ本人のアプリ専用領域です。テスト操作も実際の同期データを更新します。
- 通常版の保存キーを変更しないことを、隔離したブラウザのテストデータで確認してから公開物を作ります。
- テスト版ページには検索除外用のmetaを追加しますが、アクセス制限ではありません。URLを知っている人は開けます。デッキの同期には本人のGoogle認証が必要です。
- テスト版を含む配信では、テスト版ソースのプライバシーポリシーを両方のURLに配信します。含まない場合は通常版ソースの「公開準備中」の文面を維持します。Googleに登録済みの通常版ポリシーURLも引き続き利用できます。

## テスト版の停止

`SYNC_PREVIEW_REF` を削除してmainの配信workflowを再実行すると、次の公開物から `/sync-test/` が除かれ、ポリシーも通常版ソースの文面へ戻ります。既に開いているページや本人のGoogle Driveデータを削除する操作ではありません。

同期機能を通常版に統合するときは、通常版のv3形式対応を維持し、テスト版の保存領域からの移行方法とポリシーを見直してください。ユーザーの2026年10月17日のPC同期成功報告はありますが、スマートフォンの実Google接続・双方向同期の成功は別に確認します。

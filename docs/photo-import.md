# 写真から取り込み（試験版）

実物のカードを1枚ずつ広げた写真から、新しいデッキを作る機能です。
写真選択 → ブラウザ内で照合 → 候補・枚数の修正 → 既存のインポート確認画面、の順で操作します。
要確認の検出枠は、カードを確認・変更するか枠を削除するまで取り込めません。
見落とされたカードは検索から1枚ずつ追加できます。

## 処理と配信

- `lib/photo-import.ts`: JPEG / PNG / WebP（20MB以下、各辺100px以上、総画素数5,000万以下）を読み、長辺を最大1800pxに縮小します。
- `public/photo-reader.worker.js`: 専用のWeb Workerで輪郭検出・台形補正・画像照合を実行します。完了・中断・失敗時にはWorkerを終了します。
- `public/photo-card-index.json`: 公式カード576種類の色とORB特徴量を収録した静的索引です。
- `public/vendor/opencv-5.0.0.js`: WASMを内包したOpenCVです。出典・ライセンスは同じディレクトリにあります。
- `components/photo-import-dialog.tsx`: 要確認の絞り込み、候補変更、手動追加、メイン／サイド指定を行います。

写真を選んだときだけ、同一配信元からWorker・OpenCV・索引を読み込みます。
OpenCVと索引のファイルサイズは合計約19.2MB（転送時の圧縮前）です。
写真の画素はブラウザ内でのみ使用し、ネットワーク送信やlocalStorage保存はしません。
既存の解析用通信やカード画像の取得は従来どおりです。
画像認識用のサーバーやAPIキーは不要で、GitHub Pagesの静的配信で動きます。

## 制限

- 1つの検出枠を1枚として数えます。レシピのスクリーンショットに印字された枚数は読み取りません。
- 反射、影、カードの重なり、見切れ、よく似た絵柄では誤認識や未検出が発生します。「すべて」表示でも結果を確認してください。
- 最大64枠まで照合します。読み取りが120秒を超えると中断します。
- 自動照合は索引に含まれる公式カードが対象です。オリジナルカードは手動追加できます。
- HEICはJPEG等への変換が必要です。

## 索引の更新

公式カタログ `app/ijinden-cards.ts` を更新したら、索引も再生成してください。
生成時のみPython、NumPy、OpenCVが必要です。実行確認時はPython 3.12と
`opencv-python-headless==4.13.0.92` を使用しました。

```sh
python -m venv work/photo-index-venv
# 作成した仮想環境を有効にした後:
python -m pip install numpy opencv-python-headless==4.13.0.92
python scripts/build-photo-index.py
pnpm build:pages
```

生成スクリプトは公式カタログの画像URLから参照画像を取得し、
`work/photo-references/` にキャッシュします。ユーザーの写真は索引に含めません。
索引のカード数を変更した場合は、取込画面の対象種類数の案内も更新してください。

## 検証記録

提供された実物写真1枚を、ローカルの本番ビルドとデスクトップChromeで確認しました。
写真の36枚中35枚を検出し、31枚を正しく自動選択、4枚を要確認にしました。
3枠の候補修正、1枠の確認、見切れた1枚の手動追加後に、正解の13種類・36枚と一致しました。
これは当該写真での結果で、一般的な認識精度を保証する数値ではありません。
スマートフォン幅390pxでも操作確認しましたが、iPhone / Android実機での速度や互換性は未確認です。

利用者の写真や一時的な試験データは、Gitで無視される `work/` に置いています。

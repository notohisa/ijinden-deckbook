# Google Drive同期の設定と確認

初版は手動同期です。マイデッキの「Googleで接続」→「同期内容を確認」→「この内容で同期」で、同じGoogleアカウントを使う自分の端末間で保存済みデッキを共有します。Google OAuthクライアントIDを設定するまで接続ボタンは無効です。Google側の設定、課金状態の確認、実アカウントでの受入確認は管理者が行います。

## 管理者の設定

1. Google Cloudに同期専用プロジェクトを作成します。**請求先アカウントは紐づけません。無料トライアル・有料枠への移行は不要です。** Billing画面で「このプロジェクトには請求先アカウントがありません」を確認します。Google Cloudの別プロジェクトに支払方法があっても、このプロジェクトの紐づけを個別に確認してください。
2. Google Drive APIを有効にします。Google Auth Platformでアプリ名、サポート連絡先、外部ユーザー向けの同意画面を設定します。最初はTestingとし、自分のGoogleアカウントをテストユーザーに登録します。
3. 要求する権限は `openid`、`email`、`https://www.googleapis.com/auth/drive.appdata` だけです。アカウント識別子とメールアドレスを利用し、名前・プロフィール画像用の `profile` やDrive全体を読む権限は追加しません。以前のテストで不要な権限を許可した場合は、Googleアカウントの「サードパーティとの接続」からこのアプリの許可を取り消し、必要な権限だけで接続し直します。
4. OAuthクライアントを「ウェブアプリケーション」として作成します。「承認済みのJavaScript生成元」に必要な以下のoriginを登録します。**パスや末尾スラッシュは付けません。** この実装はGISポップアップのtoken modelを使い、アプリ側のリダイレクトURIは不要です。
   - `http://localhost:5173` と `http://127.0.0.1:5173`（ローカル開発）
   - `http://localhost:5190` と `http://127.0.0.1:5190`（ビルド結果の確認）
   - `https://notohisa.github.io`（GitHub Pages）
5. 公開クライアントID（末尾 `.apps.googleusercontent.com`）を次の方法で設定します。**クライアントシークレット、サービスアカウント鍵、アクセストークンはコードやリポジトリに入れません。**
   - ローカル：未追跡の `.env.local` に `VITE_GOOGLE_CLIENT_ID=取得した公開ID` を1行書き、開発サーバーを再起動。
   - GitHub Pages：リポジトリ Settings → Secrets and variables → Actions → Variables に `VITE_GOOGLE_CLIENT_ID` を登録し、設定済みの公開ビルドを実行。IDは公開情報なのでSecretである必要はありません。
6. 一般公開前に、同意画面のホームページ・プライバシーポリシー（`https://notohisa.github.io/ijinden-deckbook/privacy.html`）・連絡先を確認し、必要な公開設定を行います。Testingの100人制限・7日での認可失効は本番運用と異なります。ブランド審査やドメイン確認が求められる場合は、実際のGoogle Consoleの案内に従ってください。

```sh
pnpm install --frozen-lockfile
pnpm dev:pages --host 127.0.0.1 --port 5173
```

ブラウザで `http://127.0.0.1:5173/ijinden-deckbook/` を開きます。別端末でlocalhostは共有できません。スマートフォンとの実接続テストは、設定済みのHTTPS公開環境が必要です。

## 一般公開前の確認事項

- 主な想定利用者は成人の友人です。Google同期は任意とし、接続しなくてもデッキ作成・端末保存・JSON入出力を利用できます。
- [Drive API規約](https://developers.google.com/workspace/drive/api/terms)には、アプリ内のユーザー／アプリコンテンツをDriveへバックアップする用途についてGoogleの事前の書面同意を求める条項があります。appDataFolderの技術資料だけで今回のデッキ同期が適用外とは判断せず、用途の適合を確認してから同期を一般公開します。
- ホームページ、プライバシーポリシー、Google同意画面の表示を揃え、必要なブランド審査とドメイン所有確認を完了します。現在の `notohisa.github.io` で手続きが通るかは未確認です。
- 実際のGoogleアカウントを使ったPC・スマートフォン間の受入テストが必要です。模擬APIのテスト合格を、実Google接続や公開要件の確認済みとして扱いません。

## 動作とデータ保護

- 保存先は本人のDriveの非表示アプリ専用領域です。Driveの通常のファイル一覧やゴミ箱には表示されません。権限を取り消す操作とログアウトは別です。ログアウトはこのページのトークンを破棄し、デッキ自体は消しません。共用端末向けに、同期画面からプライバシーポリシー内の端末データ消去手順へ案内します。
- 各Googleアカウントの識別子ごとに端末の保存領域を分けます。未接続のデッキは「この端末だけのデッキを追加」で明示的にコピーします。アカウントを切り替えただけではコピーしません。トークンはメモリだけに保持し、再読み込み後は再接続が必要です。
- 作業中のレシピ・表示テーマはDriveに送信しません。保存済みデッキの名前、色、カードID・枚数、ゴミ箱、変更履歴だけを同期します。
- 読み込み済みの画面ではオフラインでも端末内に保存できます。オフラインでの新規起動・ページ再読み込みには対応していないため、通信が戻るまでは画面を開いたまま利用します。
- 同じ保存済みデッキを開いて保存すると同じIDを更新します。「別のデッキとして保存」は新しいIDです。JSONは同じIDだけを確認後に更新し、同名別IDは番号を付けて追加します。共有リンクは新規IDになります。
- すべての端末の内容を読み、変更履歴を比較して新しいDriveファイルへ保存します。保存成功を確認してから、最初に読み取った自端末の旧ファイルだけを削除します。別端末のファイルや、途中で追加されたファイルは削除しません。同じIDへの並行変更は利用者が選択します。時刻の新しい方を無条件に採用しません。同時同期で後から到着した変更は次の同期で検出します。ブラウザのプロファイルやlocalStorage全体を別端末に複製せず、デッキの移行には同期または標準JSONを使ってください。
- ゴミ箱はアプリ内です。削除を初めてDriveへ保存した時点から30日経過後、次の同期で完全削除します。未同期のゴミ箱は自動削除しません。手動の完全削除も可能です。復活防止用のIDと履歴は残します。過去のDriveバージョン、同期していない別端末や手動バックアップから即座に内容を消去する保証はありません。
- 同期前に、選択中アカウントのローカルバックアップを1世代保存します。「同期前バックアップ」からJSONで取得できます。標準JSONインポートはそのファイルの有効デッキだけを扱い、内部の端末IDや削除履歴を復元しません。完全な保存領域の置き換えに使わないでください。
- 読取失敗、未知の形式・カード、容量不足、401、403、429では書込を進めません。上限時に有料サービスへ切り替える処理はありません。必要になったら同期を停止し、端末保存・JSON書き出しを使います。
- 本人のDrive容量が不足した場合は「Google Driveの保存容量が不足しています。」とエラーを表示して同期を中止します。端末データは保持し、容量の購入・有料プランへの誘導は行いません。
- ローカルの保存形式はv3になります。v1/v2は読み込み後に移行します。旧アプリへ戻す場合はv3を認識できないため、事前に通常JSONを書き出してください。更新時は古いタブをすべて閉じてください。
- 初版の保護上限は1ファイル2MiB、1回の同期で読み込むファイルの合計10MiB、100端末、500ファイル、1スナップショット2万レコードです。ファイル本文は受信中にサイズを検査します。超えたデータは切り捨てず同期を止めます。利用人数の上限ではなく、1アカウント内の上限です。Cloud側の実際の割当量は別途確認が必要です。

## 受入テスト

まず既存デッキをJSONで書き出してから、少数のテスト用デッキで確認します。

1. PCでGoogle接続し、端末だけのデッキを追加して同期。別ブラウザまたはスマートフォンで同じアカウントに接続して同期し、全件・名前・カード枚数・色を確認。
2. 両方の端末で同じデッキを編集して保存し、順に同期。競合表示で片方を選ぶ、両方残す、あとで中止をそれぞれ確認。
3. 片方で削除し同期、他方へ反映。その後ゴミ箱から復元し再同期。手動完全削除後に古い端末から同期しても同じIDで復活しないことを確認。
4. 読み込み済みの画面をオフラインにして編集・保存。オンラインへ戻してから再読み込み・再接続・同期すると反映されることを確認。
5. ログアウト→別Googleアカウントへ接続し、前のアカウントのデッキが自動で混ざらないことを確認。元のアカウントに戻ると未同期の変更も残っていることを確認。
6. ポップアップを閉じる・権限を許可しない・ブラウザの容量不足・トークン期限切れで成功と表示されず、端末内容が残ることを確認。
7. Google同意画面で必要な権限だけを要求していることを確認。認証画面を閉じた際はキャンセルとして表示され、その後に再接続できることを確認。
8. Driveの容量不足で保存を拒否された際にエラーとなり、同期日時・端末データが更新されず、成功通知も出ないことを確認。
9. Google認証の準備中に通信が失敗・タイムアウトした際、通信復旧後に「再試行」から準備をやり直し、接続ボタンで認証を開始できることを確認。

単体テストは `pnpm test`。Google APIを模したブラウザテストは実アカウントへ通信せず、独立したブラウザ保存領域を使います。PowerShell例：

```powershell
$env:VITE_GOOGLE_CLIENT_ID='test-client.apps.googleusercontent.com'
pnpm build:pages
$env:SYNC_BROWSER_TESTS='1'
$env:PLAYWRIGHT_CHANNEL='chrome' # 既存Chromeを使う場合
pnpm test:browser
Remove-Item Env:VITE_GOOGLE_CLIENT_ID
Remove-Item Env:SYNC_BROWSER_TESTS
pnpm build:pages # 模擬IDのビルドを公開しない
```

CIは模擬IDのビルドでブラウザテストを行い、その後、公開用の実IDまたは未設定状態でビルドし直します。模擬テスト合格は実Google OAuthの設定成功を意味しません。

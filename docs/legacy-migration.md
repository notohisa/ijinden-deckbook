# 旧サイトからの一括移行

「インポート」または「ヘルプ」の「旧サイトからまとめて移行」から案内を開きます。

1. 書き出し用リンクをブックマークバーへドラッグして登録します。スマートフォンでは案内内の「登録用アドレスをコピー」を使い、登録済みブックマークのURLを書き換えます。
2. マイデッキを保存している端末・ブラウザで、普段使っているブックマークや閲覧履歴から旧サイトを開きます。旧サイトを表示したまま、書き出し用に登録したブックマークを実行します。
3. 保存されたJSONファイルをデッキ帳で選び、確認画面から取り込みます。

書き出しツールは外部コードを読み込まず、旧サイトの `ijinden-deck-builder` IndexedDBの `decks` ストアを読み取り専用で開きます。旧サイトの保存内容を変更・削除しません。別のサイトでの実行や、データベースがない場合は案内して終了します。未保存レシピやお気に入りカードは移行対象に含まれません。

ファイル形式は `{ version: 1, type: 'ijinden-deck-builder-backup', exportedAt, decks }`。`decks` は旧サイトの `{ id, title, timestamp, main, side }` レコード配列です。旧サイトが保存する `timestamp` はIndexedDB内では `Date`、JSON内ではISO日時文字列になります。取り込みはこの文字列と、数値のミリ秒形式に対応します。ファイルはバックアップとして保管できます。

取り込み時は、旧カード番号を新カード番号へ変換し、カード・枚数を検証します。不明なカードや不正な枚数を含むデッキは、カードを捨てて保存することなくデッキ単位でエラーとして表示します。同じメイン・サイド構成は既存デッキや同一ファイル内の重複と照合して省きます。同名で構成が違うデッキには旧番号を付け、既存デッキを上書きしません。名前がないデッキにも旧番号を付けます。

更新日時は取り込み時刻になります。元の保存日時は書き出したファイルに残ります。通常のデッキ帳JSONの「同名デッキを更新」動作は従来どおりです。

検証は `tests/legacy-deck-*.test.mjs` と `tests/browser/legacy-migration.spec.mjs`。ブラウザテストは実ユーザーのデータを使わず、隔離した旧サイト用IndexedDBから、ビルドされたブックマークレットによる書き出し・取り込み・再読込・再取り込みを確認します。
